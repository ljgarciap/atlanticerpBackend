## Observaciones (no bloqueantes)
1. BAJO — Mensaje confuso al exceder el VAR cuando también excede el saldo por cobrar. Un descuento de 200 con VAR 0 y saldo por cobrar 137.77 responde 422 con `errors.resultado: ["El campo resultado es obligatorio."]` además del error correcto de `monto`; el `message` de cabecera muestra primero lo de `resultado` ("(y 1 error más)"). Causa: `RegisterCreditNoteRequest` calcula `hayExcedente` con el monto digitado aunque ya supere el VAR. El bloqueo funciona; solo confunde. Reproducir: descuento 200 sobre F-E2E-9001 con VAR 0 (o cualquier monto > VAR y > saldo).
2. BAJO — Texto del bloqueo de "Corrección de datos" con notas previas PENDIENTES: dice "La factura ... ya tiene una corrección pendiente de aprobación de Aprobador", aunque la nota pendiente sea un descuento/devolución (reutiliza el mensaje de SCRUM-929). Con notas APLICADAS el mensaje es el correcto ("ya tiene notas de crédito (NC-0009, NC-0011) — no se puede corregir"). El bloqueo (C2/C3) sí funciona.
3. BAJO — En el modal abierto desde una Devolución de Bodega no aparece el aviso "Ya acreditado con notas previas / Valor que aún se puede acreditar" (el monto sí queda bien acotado). La precarga del frontend (`devolucionPrecargada`) pasa `monto_acreditable` pero no `notas_previas_total`, y el aviso depende de este último.
