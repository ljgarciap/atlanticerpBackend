## Hallazgo 1 — 🔴 CRÍTICO — SCRUM-865 punto 3

**AC violado:** "El campo de comprobante es obligatorio al registrar **cualquier** nueva nota de crédito/devolución; el sistema no permite guardar sin este archivo." (el ticket no define ninguna excepción; el cuerpo dice "de cualquier tipo").

**Contradicción backend ↔ frontend:**
- **Backend** — `atlanticerp-backend/app/Modules/AdminCont/Http/Requests/RegisterCreditNoteRequest.php:94`:
  `'comprobante' => ['required', 'file', 'mimes:jpg,jpeg,png,pdf', 'max:10240']` — obligatorio para **todos** los tipos, sin condición. Confirmado por el test `AdminContCreditNoteControllerTest::test_devolucion_de_mercancia_ahora_tambien_exige_comprobante` (línea ~616), que hace `assertJsonValidationErrors(['comprobante'])` para `TIPO_DEVOLUCION_MERCANCIA` sin comprobante.
- **Frontend** — `atlanticerp-frontend/src/components/admin-contab/RegistrarNotaCreditoModal.tsx:233`:
  `const comprobanteObligatorio = !esDevolucion` → para una devolución precargada de Bodega el comprobante NO es obligatorio; el botón "Registrar" queda habilitado sin adjunto (línea 249). El test `RegistrarNotaCreditoModal.test.tsx:406` (`'NUNCA obligatorio en modo Devolución, incluso superando el umbral'`) fija explícitamente ese comportamiento.

**Repro:** Notas de Crédito → cola de devoluciones confirmadas por Bodega → "Registrar nueva nota" (tipo "Devolución de mercancía") → completar monto/motivo, NO adjuntar comprobante → "Registrar" está habilitado → al enviarlo el backend responde **422 `comprobante field is required`**. La nota de devolución no puede crearse por el flujo que la UI presenta.

**Impacto:** flujo Bodega→Admin de nota de crédito roto (el caso principal del ticket 865). Antes de este batch los dos lados eran consistentes (comprobante condicional, nunca exigido en devolución); el batch dejó el backend endurecido y el frontend no.

**Fix sugerido:**
- `RegistrarNotaCreditoModal.tsx:233` → `const comprobanteObligatorio = true` (quitar el `!esDevolucion`); mostrar el asterisco + hint también en modo devolución.
- Invertir el test `RegistrarNotaCreditoModal.test.tsx:406` → "también obligatorio en modo Devolución"; revisar el test de línea 207 (`'...pero no el bloque de monto/excedente/comprobante'`) — el bloque de comprobante sí debe aparecer ahora.
- Decisión de negocio para Luis: el autor del frontend argumentó que la devolución ya trae su documento firmado de Bodega (RN2 de REQ-487). Si Luis quiere mantener esa excepción, hay que **revertir el lado backend** (`e864a54`) para que vuelva a ser condicional — pero eso contradice el texto literal del ticket. Recomendación: seguir el ticket (comprobante siempre), alinear el frontend.

## Hallazgo 2 — 🟠 MAYOR — SCRUM-870 punto 2

**AC violado:** "Los rangos de comisión deben mostrarse como: **'Menos de $15K → 1%'**, '$15K – $19K → 1.5%', 'Más de $20K → 2%'."

**Observado (Playwright, `/admin-contab/reportes`, login Contabilidad — captura `e2e/screenshots/SCRUM-870-2-contabilidad-tiers.png`):**
La lista de tramos de la tarjeta "Comisión por gestión de cartera +90 días — Contabilidad" renderiza:
```
Menos de $14K → 1%        ← debería ser "$15K"
$15K – $19K → 1.5%        ✓
Más de $20K → 2%          ✓
```
El badge separado "RANGO ACTUAL" de la misma tarjeta sí muestra "Menos de $15K" → las dos referencias de la misma tarjeta quedan inconsistentes entre sí.

**Causa raíz:** `atlanticerp-frontend/src/pages/admin-contab/ReportesPage.tsx` — `formatCompactK(value) = \`$${Math.floor(value / 1000)}K\``. El tramo 1 tiene `monto_maximo = 14999.99` (migración `2026_08_27_100002_create_admin_contab_cartera_commission_tiers_table.php`), y `Math.floor(14999.99/1000) = 14`.
El unit test `ReportesPage.test.tsx` (`'SCRUM-870: Contabilidad commission tiers show the compact K format'`) usa un fixture con boundary `15000` (redondo), no `14999.99`, así que no detecta el off-by-one.

**Fix sugerido:** en la rama del primer tramo (`tier.monto_minimo === 0`, texto "Menos de X"), X es un tope **exclusivo** = el `monto_minimo` del tramo siguiente. Usar `Math.ceil(value/1000)` ahí, o mirar el `monto_minimo` del siguiente tier. Dejar `Math.floor` (truncar) solo para el `hasta` de un rango cerrado ("$15K – $19K"). Actualizar el fixture del unit test a los boundaries reales con `.99`.

**Regresión guard:** `e2e/preqa-batch-scrum864-870-20260909.spec.ts` → test `SCRUM-870.2` — hoy en **ROJO**, pasa cuando el fix aterrice.
