## Nota operativa — hallazgo de harness, no de producto

Al armar el script de Pre-QA con `Artisan::call()` dentro de `artisan tinker --execute`, el
extractor fakeado vía `app()->instance()` era ignorado — el comando terminaba conectándose a ICG
real (`SQLSTATE[HYT00]: Login timeout expired`, host `192.168.101.4`) pese al binding. Causa raíz
diagnosticada: `Kernel::commands()` resuelve y cachea (con sus dependencias ya inyectadas) TODOS
los comandos auto-descubiertos al bootstrapear el proceso `artisan` externo — **antes** de que el
script de `--execute` corra `app()->instance()`. `Artisan::call()` reutiliza esa instancia ya
cacheada con el extractor real, no una nueva. Confirmado con un diagnóstico directo: resolver el
comando fresco vía `app($commandClass)` **sí** respeta el binding. Fix del harness: reemplazar
`Artisan::call()` por `app($commandClass)->run($input, $output)` (con `setLaravel(app())` explícito
— sin eso, `Command::run()` falla con "Call to a member function make() on null"). No es un bug de
SCRUM-840/841/842, es un gotcha de cómo testear comandos Artisan fuera de PHPUnit (que sí evita
esto al re-crear la aplicación completa por test, antes de bindear el fake).
